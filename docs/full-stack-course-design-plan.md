# 任务方案：全栈工程师成长课程

本文件记录课程设计依据与获批执行快照；面向学习者的完整课表见 [COURSE_PLAN.md](../COURSE_PLAN.md)。用户已批准当前课程方案，并要求在检查无误后提交 Git。课程实验、依赖安装、部署和学情验收尚未执行；本轮只交付并验证课程文档，不把未来课程状态标为已掌握。

## 任务事实与边界

- 表面任务：为初学者设计在 AI 协助下逐步构建、诊断和维护全栈应用的课程安排文件。
- REQ-01：包含成长路径、阶段、逐课主线、知识、方法、诊断训练与进入下一课的验收。
- REQ-02：保持 AI 修改文件、学习者审查 diff 与解释证据的协作习惯。
- F-01：已读取 AGENT.md、README.md、前后端 package.json、App.tsx、server.ts；当前技术栈是 React、TypeScript、Vite、Express、npm workspaces。
- F-02：源码有前后端空姓名校验、分步日志、POST /api/hello；没有数据库、用户账户或自动化测试脚本。
- F-03：会话记录显示已接触启动、端口、请求响应、Sources、校验绕过和预检；不能据此认定学习者已经通过独立验收。
- F-04：README 留空提交得到 400 的说明落后于当前页面校验行为；课程需区分页面阻止请求与直接请求后端。
- C-01：本轮交付本地 Markdown 课程方案并提交 Git；不执行后续课程、不安装依赖、不修改业务代码、不发布。
- C-02：后续故障实验限定隔离的本地练习环境和合成数据；恢复与验证是课程验收的一部分。
- U-01：每周可用时间、独立编程基础、最终职业侧重未知；以入门测评、可调课时及共同主线后选修处理。
- ASM-01：优先沿用现有技术栈，以学习记录/小型协作任务系统串联课程，降低反复切换工具和业务的负担。
- 输入/工具/权限：项目只读检查、用户提供的会话、官方资料、本地课程方案保存权限、Markdown 与计划校验器。

## 战略路由与模块选择

- 任务特征：不确定性为学习基础未测；依赖为前端到数据再到权限部署的链式先修；可逆性为文档可修改；范围/能力为初学者与 AI 角色分工；遗留惯性为已有实验习惯；环境动态为具体工具版本以后需重核；协调复杂度为单个学习者与 AI。

## 关键挑战诊断

- D-01 | 如果学习者长期只复现 AI 给出的成功操作，就可能无法在新故障里识别数据停在哪一层；继续增加功能会扩大代码量，却不保证形成可迁移的工程判断。
- 支持链：F-01/F-02 提供可观察系统；F-03 只有接触记录，缺少变式题与独立诊断证据；REQ-01 要求按掌握程度推进，故每课必须产出判断证据。
- 为何关键：接口、数据库、权限、部署错误会相互叠加；前层判断缺失会导致后层实验依靠猜测。
- ALT-01 | 先系统学完语言、算法再做项目。优点是基础集中；缺点是离当前问题远、反馈慢。若最小对象读取、条件判断也不能解释，则局部回到语言补课，而非停止所有项目实践。
- ALT-02 | 尽快让 AI 生成完整复杂产品，再逐步阅读。优点是产物快；缺点是变化变量太多，难以归因。只在毕业项目具备切片验收能力后采用较大范围生成。
- 反证条件：若学习者在陌生场景中持续能预测、定位并验证修复，则缩短基础讲解，通过挑战验收进入后续阶段，不重复已掌握内容。

## 指导方针

- G-01 | 优先用一个项目的完整数据链，按一次新增一种主要复杂性的顺序教学；每课以解释、证据、变式、恢复四项验收决定推进。排除按框架数量安排成长的路线。
- G-02 | AI 负责经授权的代码修改、示范和检查；学习者负责预测、选择观察位置、审查 diff、解释因果与批准关键取舍。逐渐撤去答案提示，保留 AI 编码帮助。
- 优先级：数据流与语言基础 → 持久化与业务 → 权限 → 测试与交付 → 性能与架构 → 方向深化。
- AI 自主范围：保存方案与核对课程完整性；后续只在当前获准课程范围操作。
- 必须询问条件：真实部署、付费、外部写入、真实数据、破坏性操作或实质扩大实验范围；无此情况不增加课程文件审批环节。
- NG-01 | 不以完成视频、阅读时长、AI 口头评价或仅构建成功替代学习验收。
- NG-02 | 不同时切换多套语言和框架，不把微服务、容器编排与 AI 产品功能列为初学者全栈必修。

## 近端目标与杠杆点

- O-01 | 下一次教学先完成已接触知识的短测与 L08 字段契约实验，产出一次由学习者解释的失败证据链和恢复结果；本轮交付完整、可审阅的课程安排，不宣称该学习目标已经达成。
- 可行性：现有项目已具备请求、响应、日志及校验；无需为第一轮测评引入数据库。
- L-01 | 以“正常—单点故障—定位—最小修复—回归”的重复结构降低认知负担；把练习投入集中在跨层观察与因果解释。
- 减少未知：入门测评区分语言阅读不足、观察工具不熟和协议概念不清，决定具体补课位置。
- 杠杆失效信号：连续两课只能背诵修复答案、不能在换字段或换入口后定位；退回最小语言/HTTP 练习，缩小实验。
- 暂不追求的终局：本轮不保证就业、高并发架构能力或全方向专家水平。

## 链式弱环节与风险

- W-01 | 主链为语言/数据流 → API → 数据库 → 权限 → 交付 → 架构；任一先修不过则阻止相关下游实作。课程顺序串行，独立阅读不计通过。
- W-02：AI 同时命题、写代码、解释时可能造成虚假熟练；以学习者先提交预测、实际日志和换场景复测作为进入闸门。评分不确定时标记待复测。
- W-03：当前 README 与校验代码存在局部不一致；第一课用源码和实际请求核对，不能按过时文档把“没发请求”诊断为后端失败。本轮只在课表提示，不顺手改 README。
- 中止条件：实验数据或目标超出隔离范围、恢复点不明、连续两次变式失败；分别回到权限、输入或 G-01 的教学粒度调整。
- 整合判断：共同主线不能用选修抵扣；复杂度只在上一阶段验收之后增加。

## 假设与失败信号

- H-01 | 单点故障加三处证据对照可训练迁移判断。预期观察：在字段名变化的陌生变式中，学习者能先指出比较 Payload 与后端读取字段，再解释 400。最小验证：L08 一次训练题加一次不透露原因的同层变式。通过标准：四维评分均为 2，并恢复正常请求。失败信号：只记得修改哪一行，不能解释原因或选择证据；重查 D-01 是语言基础不足还是观察方法不足，调整 G-01 的粒度。
- H-02：沿用技术栈可减少无关安装成本。最小验证：头两课检查启动和文件定位；若主要时间耗在环境，则先用已有运行环境教学并单独补环境课，不更换全套技术。
- 独立证据：实际请求、日志、测试输出与学习者先行回答；AI 的自信不作通过依据。
