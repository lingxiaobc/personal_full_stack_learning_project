# L11 学习进度｜HTML、CSS 与浏览器实际呈现

日期：2026-10-02

状态：真实故障练习及恢复回归已完成；独立变式待复测，尚不记录为 L11 正式通过或阶段 2 完成。

## 已观察与理解

- 用 Elements 选中目标元素，再结合 Styles/Computed 找生效规则；区分源码中的 JSX、运行时 DOM 和 CSS 呈现。开发者工具里临时修改样式，刷新后会恢复源码定义的规则。
- 通过盒模型观察父子元素各自的 content、padding、border 和 margin；margin 本身不填充背景色。
- 观察 `.workspace-grid` 的宽屏双列与窄屏媒体查询。一次受控故障中，窄屏仍显示双列；学习者找到了容器和媒体查询，但起初把生效的 `repeat(2, minmax(0, 1fr))` 判断为未生效或语法错误。核对后明确：原声明被划掉，新声明生效，且 `repeat(2, ...)` 本身就是两列。源码已恢复为 `1fr`。
- 一次标签关联故障中，点击“姓名”不再聚焦输入框。学习者发现交互异常并查看 Elements，起初归因为缺少点击事件；核对 `label` 的 `for` 与 `input` 的 `id` 不匹配后，明确这是浏览器原生的标签关联行为，不需要单独绑定点击处理函数。源码已恢复。
- 一次结果可见性故障中，页面 Request/Response 区显示 HTTP 200 和返回内容，`div.result.success` 中也已有问候语，但左侧结果不可见。学习者选中正确元素，发现父元素上的 `visibility: hidden`，禁用该规则后问候语出现；由此区分数据已进入 DOM 与用户实际可见。源码已恢复。
- 曾用 Sources 断点观察表单提交处理函数：空姓名分支在 `fetch` 前返回；区分“事件已触发”与“请求已发出”。

## 验证与限制

- 三次实验每次只引入一处主要故障，诊断后分别恢复；最终 `git status` 与 `git diff` 无残留实验改动。恢复后前端 `npm run build --workspace frontend` 通过。
- 学习者在恢复后确认：窄屏单列、点击姓名聚焦、非空姓名提交后问候语可见。截图中还显示成功响应及页面 DOM 内容。
- 本轮故障诊断获得了 AI 的观察提示，前两项最初的因果判断需要纠正。因此它们作为练习证据，不冒充无提示迁移或四维全 2 分的正式验收；进入 L12 前仍需新的独立变式复测。
